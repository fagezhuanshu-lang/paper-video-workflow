# 在 WorkBuddy 或其他桌面代理中使用

本仓库提供文件合同、CLI和技能说明，不绑定某个聊天模型。**WorkBuddy端到端接入尚未实测**；不要把下面步骤理解为已认证兼容或保证与任何演示逐帧一致。

宿主需要能读取本地项目和媒体、编辑JSON、运行Node/FFmpeg子进程、查看生成图片与视频，并允许用户进行实际试听。只能访问网页链接的聊天窗口无法完成本地渲染。宿主的按钮名称、技能导入方式和权限设置以你安装版本的实际功能为准。

## 建立环境

升级到 v2.1 时用新文件夹打开解压后的整个工程，在安装后运行 `.\Run.ps1 --version`，应显示 `2.1.0`。想复现 MotionGit 试片时，让助手按[原生制作说明](motiongit-native.md)检查模板授权和本机工具；缺项时说明并保留进度，不能直接改用公开引擎。选择随包原创风格时按下方步骤执行。

1. 从仓库的明确版本/提交下载或克隆完整目录，保留文件结构；不要只复制SKILL.md。
2. 终端进入仓库根目录，按 README 运行 `Setup.ps1`；安装器会复用完整的 Node.js 22+/npm，或准备本项目内的便携运行时。已有完整 Node/npm 时也可使用 `npm ci`。
3. Windows 运行 `.\Run.ps1 doctor`。修复明确指出的字体、原生模块、FFmpeg或路径问题，再继续。首次安装可能需要联网下载依赖；公开引擎制作本身不需要购买模型额度或调用收费素材API。
4. 运行 `.\Run.ps1 demo` 做合成素材测试。它只能证明当前环境在该演示输入下运行；不能证明中文ASR、真人口播剪口、真实音乐混音或审美已经通过。具备全局 Node 时，以上命令也可写成 `node cli.mjs doctor` 和 `node cli.mjs demo`。
5. 在桌面代理中打开完整仓库，让它读取SKILL.md、docs/project-format.md和CONTRACT.json。若宿主支持技能安装，可按该宿主的官方方式安装整个目录；仓库不假设某个产品的私有技能目录。

可直接提供这样的任务：

> 阅读本仓库 SKILL.md 和 CONTRACT.json，确认版本为 2.1.0。我本次选择随包的公开纸面风格。先运行 doctor，使用我提供的原片和真实字幕，保持原话意思，给出有证据的 project.json，运行 validate 后再 build。检查人物大窗到小窗及返回过程、字幕、音轨与两张封面，再交付视频、封面、字幕和实际检查结果。不要重写渲染器，不调用收费服务，不把没听过的 ASR 标成已经复核。

需要之前的 MotionGit 原生效果时，改用这段任务：

> 阅读 SKILL.md 和 docs/motiongit-native.md。我要求使用自己的 MotionGit 原生模板，请检查我已提供的授权包、官方工具与依赖，读取实际工作流合同后制作。按官方流程预览、渲染，再配独立主题封面。缺项时报告具体缺口并保留已完成工作，不要自动切换到公开引擎。交付时注明所用引擎、模板版本和实际检查范围。

素材不足时应记录具体缺口；只有转写需要另补时才处理该缺口，不重复索要已提供文件。没有自动ASR不妨碍用用户现成字幕运行。

## 模型能力与复现

固定代码降低了路径处理、图片排版、混音和编码的临场编程需求。模型仍负责辨别否定/条件、挑选受原话支持的场景、准确绑定时码、选择封面和检查结果。较弱模型应先使用已审核的计划运行，再逐步开放新内容策划；不能通过把所有review设为true代替能力。

尽量锁定仓库版本、依赖锁文件、字体、源文件与计划哈希、输出规格和音乐来源。相同计划重跑可检查技术一致性；新素材的内容正确性需要重新验收。不同机器、原生库、字体或编码器版本也可能导致字节差异。

新Windows安装、WorkBuddy真实使用、新片与新模型应分别测试并记录环境。一次本机demo或迁移到另一文件夹，不等于完成了干净电脑验证。

# 项目格式与时间轴

字段合同以仓库根目录的 [CONTRACT.json](../CONTRACT.json) 和 `node cli.mjs validate project.json` 的实际结果为准。本页解释内容判断与时间含义，不替代验证器。

在项目JSON中填写真实素材路径。相对路径相对于项目JSON所在目录解析；运行器内部传递绝对路径。路径可含中文和空格，不需要移动原片或修改系统用户名。

| 字段 | 用途 |
| --- | --- |
| `source.video` | 本地原片；公开仓库不包含用户视频 |
| `source.start/end` | 唯一连续的保留区间，原片绝对秒数 |
| `output.width/height/fps` | 受当前验证器支持的输出规格；不凭空修改为“原片无损” |
| `captions` | `start/end/text`，真实完整句字幕，时间从所选片段0秒起算 |
| `scenes` | `start/end/kind/title/items/cues`，根据真实内容编排 |
| `music` | 用户可用的真实本地文件、增益、许可和来源；明确不配乐时按合同填空值 |
| `sfx` | 是否启用原创程序动作提示音及增益 |
| `cover` | 全文主题、证据、短标题、图形类型和可选真实选帧 |
| `review` | 文案、语义计划和封面选题实际检查状态，不是自动批准开关 |

例如保留原片10–18秒，则源片12秒处的话语在字幕时间轴上是2秒；想用这一帧做封面时 `cover.photoTime` 仍填12。不要再次减去起点。此版本没有通用多剪口编辑映射；需要删中间口误时须先使用明确的外部剪辑流程，保留其对应关系与原片。

## 封面合同

封面标题与画面判断由执行者完成，脚本负责稳定排版与导出。

| 字段 | 约束 |
| --- | --- |
| `titleLines` | 恰好两行，每行1–7字符；字母也计数 |
| `kicker` | 主题标签，1–16字符 |
| `deck` | 一个补充角度，1–21字符，不重复大标题 |
| `themeSummary` | 全文中心主题，同时符合本次保留内容 |
| `evidence` | 非空原文引述字符串列表；验证器检查原文包含关系，是否真实支持仍需人工审阅 |
| `visual.kind` | `process`、`contrast`、`claim` |
| `visual.label` | 图形说明，1–12字符 |
| `visual.labels` | 每项1–7字符；过程1–3项、对比恰好2项、观点恰好1项 |
| `photoTime` | 可省略；存在时为原片绝对秒数，并须在本次选中的 `source.start` 至 `source.end` 区间内 |

“有免费额度，超额才收费”不能概括为“永久免费”。“简单总结”和“批量长文”可以按真实需求对比，但不是三个办理步骤。不要让版式替你决定文章含义。

封面模块在构建工作目录的 `cover/` 下生成两种画幅：1080×1920和1080×1440，各有PNG、JPG及270px宽缩略图，并保存 `cover-report.json`。如抽取原片画面，还保留 `source-frame.png` 及来源时刻。图像默认等比完整放入相框；不合成人脸。

封面报告初始人工检查项均为false。文本宽度检查、图片哈希和尺寸不能代替全尺寸/缩略图审阅；脚本拒绝覆盖已有 `cover/`。重新制作使用新的构建目录。

## 校验与复核

`title`、`quote` 默认使用大人物窗，`steps`、`compare` 使用小方窗。脚本从场景时码生成关键帧并在两种景别间连续插值。相同景别连续出现时人物窗保持稳定。场景可选 `"presenter":"large"` 或 `"presenter":"compact"` 指定景别。例如步骤结束时仍要突出人物，就在下一段场景中设为 `large`。构建后查看 `presenter-motion.json`，其中坐标以 720×1280 为单位，时码从所选片段开头起算。导出 MP4 已合成这些运动。

默认按窗裁切原画面。顶部容易切到头时可以在项目根部设置 `"presenter":{"fit":"cover","anchorY":0.3}`，其中 0 对齐上缘，1 对齐下缘。需要展示整个原片时设置 `"fit":"contain"`。暂停观察同一切换前、中、后的成片，核对人物的脸和字幕。

先运行 `node cli.mjs validate project.json`，再运行 `node cli.mjs build project.json`。错误消息若涉及字段、时间或文件，应修复对应来源，不改程序跳过检查。渲染完成后分别记录机器检查结果、实际视觉/试听结论以及用户是否评价；没有做过的检查不能记为通过。
